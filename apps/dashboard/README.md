# @stark/dashboard

The Stark app, where people add bills, pay them, set limits, add money and talk to Stark.
[TanStack Start](https://tanstack.com/start) in SPA mode with file-based routes, and
[TanStack Query](https://tanstack.com/query) for every API call. UI pieces come from
[`@stark/ui`](../../packages/ui); the typed `/v1` client, query options and mutations
come from [`@stark/api`](../../packages/api).

## Commands

From the repo root:

| Command | What it does |
|---|---|
| `bun dev` | dashboard, website and backend together |
| `bun dev:dashboard` | dashboard alone → http://localhost:5174 (start the backend too) |
| `bun build:dashboard` | static SPA → `apps/dashboard/dist/client/` |
| `bun start:dashboard` | serve the build on :5174 |
| `bun --filter @stark/dashboard typecheck` | `tsc --noEmit` |

The dev and preview servers proxy `/v1` to the backend on `127.0.0.1:8000`, so the app
calls the API on the same origin and no CORS setup is needed.

## Layout

```
src/router.tsx            router + QueryClient; QueryClientProvider is the router's Wrap
src/routes/__root.tsx     document head, fonts, 404
src/routes/_app.tsx       app shell (header, desktop dock, phone tab bar); loads /v1/state
src/routes/_app/…         Home, Bills, Bill detail, Add bill, Pay, Activity, Wallet, Add money, Settings
src/routes/start/…        3-step setup: sign up, first bill, add money
src/routes/talk.tsx       full-screen voice screen
src/components/           app-only pieces (shell, bill row, forms, token card)
src/lib/                  bill and receipt display rules, Web Speech wrapper
src/routeTree.gen.ts      generated by the router plugin; committed, never edited
```

Data flow: a route `loader` calls `queryClient.ensureQueryData(xQuery())`, the component
reads it with `useSuspenseQuery(xQuery())`, and mutations from `@stark/api` invalidate the
balance, bills and activity keys so every screen stays in step.

## Environment

| Variable | Default | Used for |
|---|---|---|
| `VITE_STARK_API_URL` | empty (same origin, via the proxy) | API base URL for a deployed build |
| `VITE_STARK_LIVE_PAYMENTS` | unset | set to `1` once tokens are real; until then tokens are labelled samples |

## Rules

These come from [`docs/FRONTEND.md`](../../docs/FRONTEND.md) and are enforced in code:

- Branch on the error `code`, never on `message`. Copy lives in `errorCopy()` in `@stark/api`.
- A payment is done only when its status is `delivered`. `pending` never shows as success;
  `declined` reads "Stark stopped this".
- Never render `tx_hash` or `actions`. No "vault", "USDC" or addresses in the UI.
- Amounts are typed fields plus quick-pick chips. No sliders.
- Every screen has a phone layout (bottom tab bar under `md`).
- The Talk screen plays `VoiceReply.audio` when present (a WAV data URL from the local
  voice sidecar) and never blocks on it — the text `reply` is always shown.

## Not wired yet

- Sign-in: the setup screens continue without an account because the API has no auth.
- Adding money is a ledger-only demo, and tokens are dry-run samples.
- Auto top-up, per-bill pause and notification toggles from the designs have no API yet,
  so they are not shown.
